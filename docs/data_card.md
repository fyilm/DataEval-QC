## 2. 来源构成

三源混合，这是本数据集的设计核心：

| 来源 | 数量 | 占比 | 生成方式 | 缺陷来源 |
|---|---|---|---|---|
| `real` | 1500 | 15.5% | HuggingFace COCO parquet 采集 + 质量筛查 | **无缺陷**（作为干净母图） |
| `procedural` | 6200 | 63.9% | 程序化降级（OpenCV 算子） | 六类可控降级，三档强度 |
| `aigc` | 2000 | 20.6% | 编辑变异（泊松噪声/雾/雨/色散/泥浆/暗角/泛光等） | 与 procedural **机制不同**的退化 |

**为什么 procedural 和 aigc 要分开**：两者制造缺陷的物理机制刻意不同（前者是确定性算子，后者引入泊松-高斯混合噪声、大气散射等更接近真实的退化），目的是让模型学到缺陷本身的语义，而不是记住某一种噪声纹理。这一点在消融实验里可以直接验证。

### 2.1 真实帧采集标准

采集自 `detection-datasets/coco` 的 parquet 分片，扫描 1908 张筛除 408 张后得到 1500 张。筛查阈值：

| 指标 | 常规帧 | 夜间帧 |
|---|---|---|
| 短边 | ≥ 320 | ≥ 320 |
| 长边 | ≤ 960 | ≤ 960 |
| 拉普拉斯方差（清晰度） | ≥ 80 | ≥ 60 |
| 平均亮度 | 45 – 225 | 18 – 88 |

夜间帧设了 300 张专项配额 —— COCO 里夜景天然稀少（实测扫描 1500 张只有 55 张符合夜间标准），不做配额的话 night 场景会严重欠采样。

### 2.2 场景分布

| 场景 | 数量 | 占比 | 判定规则 |
|---|---|---|---|
| `outdoor` | 6270 | 64.6% | 天空 + 植被像素占比 > 0.18 |
| `night` | 1964 | 20.2% | 平均亮度 < 60，或亮度 < 95 且 B 通道显著高于 R/G |
| `indoor` | 1466 | 15.1% | 其余 |

## 3. 标注体系

六类缺陷，多标签：

| 标签 | 中文 | 生成方式 | 正样本数 |
|---|---|---|---|
| `low_res` | 低分辨率 | 下采样 1.5×–6.0× | 1579 |
| `blur` | 模糊 | 运动模糊核 / 高斯核，核长 3–25 | 1650 |
| `over_expo` | 过曝 | gamma 0.32–0.88，severe 档叠加高光截断 | 1566 |
| `dark` | 欠曝/黑屏 | gamma 1.4–4.5，severe 档叠加对比度坍缩 | 1654 |
| `occlusion` | 遮挡/污渍 | 纯色/噪声/暗块/污渍四种贴片 | 1687 |
| `noise` | 压缩噪声 | JPEG quality 5–68，severe 档叠加高斯噪声 | 1675 |

- **强度三档** → **难度三档**：`mild → hard`、`moderate → mid`、`severe → easy`。强度越强，缺陷越明显，样本越"容易"。
- 多标签比例约 25%（`multi_label_prob=0.25`）。
- 完整判定边界见 [`annotation_spec.md`](annotation_spec.md)，含两两边界消解规则与冲突优先级链。

### 3.1 标签的性质（重要）

这里的标签是**生成时已知的构造标签（weak label by construction）**，不是人工逐个标注的结果。

- 优点：零标注成本、无标注噪声、规模可扩展；
- 代价：标签只反映"施加了什么降级"，不反映"人眼是否真的认为这是缺陷"。
- 因此一致性核对环节（`src.label_vlm`）专门用来衡量构造标签与模型感知之间的差距，并把不一致样本送人工复核。

## 4. 切分与防泄漏

按 `origin_id`（母图 ID）**分组切分**，而不是按样本随机切分 —— 同一个母图派生的所有变体必然落在同一个 split。

| split | 母图组数 | 样本数 | real | procedural | aigc |
|---|---|---|---|---|---|
| train | 895 | 5665 | 895 | 3580 | 1190 |
| val | 255 | 1616 | 255 | 1020 | 341 |
| test | 129 | 819 | 129 | 516 | 174 |
| eval（池） | 221 | 1600 | 221 | 1084 | 295 |

注：`eval` 行的 1600 是**评测池**（`src.split` 预留出来的母图组全集）。从中分层抽出 1200 张、再补录 200 张长尾，构成实际冻结的 **1400 张评测集**；池里未被抽中的样本不参与任何训练，也不属于冻结评测集。

**泄漏自检**：1500 个母图组，跨 split 的组数 **0** —— 通过。

为什么必须分组切分：如果不做，同一张母图的"原图 + 低清版 + 模糊版"会同时出现在 train 和 test，模型靠记住母图内容就能作弊，指标会虚高。这是合成数据集最典型的泄漏陷阱。

### 4.1 评测集（冻结）

`data/eval/eval_v1.jsonl`，共 **1600 张**：

- **1400 张分层抽样**：缺陷类型 7（6 类 + normal）× 场景 3 × 难度 3 = 57 个分层格，等额起步 + 缺额回补，57 格**全部填满**；
- **200 张长尾补录**：backlit（逆光）、rain_fog（雨雾）、smudge（污渍）、smear（拖影）、dark_compressed（暗光压缩）各 40 张。长尾样本**必须来自与评测池相同的母图集合**，否则会引入新的泄漏。

冻结口径与变更流程见 [`sampling_spec.md`](sampling_spec.md)，变更历史见 [`evalset_changelog.md`](evalset_changelog.md)。

## 5. 去重

pHash（64 位）跨源比对，汉明距离阈值 **4**。

| 项 | 值 |
|---|---|
| 比对总数 | 9500 |
| 剔除 | **0** |
| 跨源近似对 | **0** |
| 跳过的同母图对 | 15550 |

**关键设计**：只在 `origin_id` 不同的样本之间比对。合成样本与其母图天然高度相似，若全局比对会把合成数据整批误删。15550 对同母图样本按设计保留。

## 6. 已知偏差与使用限制

这一节是数据卡最重要的部分。

### 6.1 域差距

- 真实帧来自 **COCO 自然图像**，不是监控画面。缺少鱼眼畸变、红外灰阶、OSD 时间戳叠加、低码率 H.264 块效应等监控特有的退化形态。
- 缺陷是**后处理施加**的，与真实退化机制不同：真实运动模糊来自曝光期间相对运动，真实噪声来自传感器读出与 ISP 管线，两者的频谱特征与程序化模拟并不完全一致。

**因此：本数据集上的指标不能等同于真实产线质检性能。** 它的用途是做可控的方法学对比（数据配比、校准、分层评测），不是部署性能承诺。

### 6.2 分布偏差

- 场景严重不均：outdoor 64.6% vs indoor 15.1%。
- 六类缺陷数量接近均衡（1566–1687），这与真实质检中的长尾分布相反 —— 真实场景中遮挡和黑屏可能占绝大多数。
- 多标签比例固定 25%，真实比例未知。

### 6.3 构造标签的偏差

- "干净帧"的判定基于客观指标（亮度、拉普拉斯方差），但真实质检中"是否可接受"带主观性。
- COCO 本身已经是经过筛选的高质量图像，本数据集又用 `lap_var ≥ 80` 再筛一遍，因此**干净基线偏高**，模型可能学不会容忍真实场景里的轻微退化。

### 6.4 第三源的实现差异

- 当前 `aigc` 2000 张是**编辑变异**实现，不是扩散模型生成 —— 本机无 NVIDIA 显卡，SD 推理在 CPU 上不现实。
- 这意味着三源混合里的第三源与第二源在"是否由神经网络生成"这一点上并未真正区分开。租到 GPU 后应重跑 `src.aigc --backend sd` 得到真实扩散样本，并重新评估。这一点已在 `docs/gpu_plan.md` 中列为 GPU 上的必做项。

### 6.5 不适用

- ❌ 不可用于宣称真实产线质检准确率
- ❌ 不可用于缺陷定位/分割（只有图像级标签，无 bbox 或 mask）
- ❌ 不可用于时序一致性相关任务（帧间无关联）

## 7. 复现

```bash
uv sync
uv run python -m src.collect  --num 1200 --night-quota 300
uv run python -m src.degrade  --num 6000
uv run python -m src.aigc    --num 2000 --backend edit
uv run python -m src.dedup
uv run python -m src.split
uv run python -m src.evalset
```

固定 seed（42）下可复现。全过程约 10 分钟（CPU）。
